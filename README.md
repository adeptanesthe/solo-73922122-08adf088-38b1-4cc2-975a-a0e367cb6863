# 再生塑料配方试配筛选（质检模型 + 最优改配求解 + 送检选样）

面向再生塑料配方研究员的网页工具，含两个页面：

1. **试配求解**（`/`）：录入原配方与各原料的上下限、锁定项后，在**合格概率 ≥ 0.7**
   的约束下，按 **先最少改变原料种数、再最小化总克数改变量** 的字典序求出最优试配方案；
   只有求解器**证明**无解才报无解，求解失败单独报告。
2. **送检选样**（`/select`）：录入 0～20 条已检配方、10～60 条待检配方与 1～5 个送检名额，
   按随机森林**叶节点覆盖收益**（叶收益 = 1/该叶训练样本数）在名额内穷举最优送检组合；
   无增量收益不推荐送检，未能证明最优时保持待定。

## 技术栈与模型

- **FastAPI** 提供网页与 JSON API；**scikit-learn** 训练随机森林；**z3-solver** 求解。
- 质检模型：`RandomForestClassifier(n_estimators=5, max_depth=3, random_state=20241117)`，
  在固定种子生成的合成数据上训练（Dirichlet 采样的配方比例 + 含噪质检规则，阈值取中位数
  使类别均衡）。每次启动以同一种子重训，结果确定（自测第 1 项验证同种子重训一致）。
- 配方为 4 种原料的整数克数，总重 1000 克；模型输入为克数 ÷ 1000 的 **float32** 比例。

## 求解语义（与分类器严格一致）

- sklearn 树内部以 float32 特征与 float64 阈值比较。求解器把每个分裂条件
  `float32(g/1000) <= τ` 预计算为等价的**整数截断** `g <= K`（`app/model.py: cutoff_left`），
  因此 z3 中的约束与原分类器的实际阈值语义逐点一致（自测第 2 项对全部阈值 × 0–1000 克逐点核对）。
- 森林概率 = 5 片叶子概率（精确有理数）之和 / 5 ≥ 0.7，以精确有理数编码进 z3。
- 字典序优化用**两阶段**实现：先最小化改动种数，固定该最优值后再最小化总改动克数。
- 每份建议解出后**用原 sklearn 分类器复算概率**（float32 输入），未通过复核则按求解失败上报，
  绝不当作合格建议展示。
- 结果状态严格区分：`ok`（已证明最优）/ `infeasible`（z3 判定 unsat，即证明无解）/
  `invalid`（输入不合法）/ `solver_failure`（z3 unknown、超时或异常，**不**当作无解）。

## 送检选样语义（`/select`，`app/selection.py`）

- 每条配方仍是总重 1000 克的 4 种原料整数克数；模型输入沿用克数 ÷ 1000 的 **float32** 比例，
  按与分类器完全相同的走树规则（`cutoff_left` 整数截断）把配方路由到 5 棵树的各一个叶。
- 全森林 40 个叶统一编号为位掩码；叶收益 = **1 / 该叶训练样本数**
  （取自 sklearn `tree_.n_node_samples`，自测与 sklearn 逐叶核对）。
- **已检配方覆盖的叶不再计入**；同一叶被多条待检配方命中**只计一次**（位掩码天然去重）。
- 在 1～名额条待检配方中，用**分支定界穷举**找总收益最高的组合；收益同分时**送检条数最少**。
  - 收益用 LCM 放大后的精确整数比较（等价于精确分数，无浮点误差），上界为
    “剩余候选中 r 个最大单候选增量收益之和”（可证有效的剪枝上界）。
  - 60 条候选、5 名额的最坏构造（60 个互异叶掩码）实测约 30ms 完成、仅数百节点；
    最优性另用 Python 暴力枚举全部组合对照（自测第 9 项，含完整 C(60,5) 对照）。
  - 时间/节点预算为防御性兜底：预算内未证最优则返回 `pending`（**待定，不给建议**），
    正常参数范围实测不会触及。
- 待检池整体无增量叶时返回 `ok` 但**不推荐送检**（空组合、收益 0）。
- 状态：`ok`（已穷举证明最优，含“不推荐”）/ `pending`（未能证明最优，保持待定）/
  `invalid`（数量越界、非整数、总重非 1000、同组重复等）。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地开发

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 页面与交互

- **试配求解页**：4 种原料的原配方克数、各自下限/上限、锁定勾选；总重须为 1000 克。
  - 「载入可行样例」「载入无解样例」：样例在服务启动时由真实模型 + 求解器**实测验证**后生成
    （`app/samples.py`），可行样例含锁定项，无解样例为上下限把配方逼入不合格区域的情形。
  - **计算期间可随时修改**：任何输入修改会立即撤下旧建议（清空结果区）、中止在途请求；
    迟到的旧响应按请求序号（epoch）比对后直接丢弃，不会恢复显示（`app/static/index.html`）。
  - 结果展示：合格概率（原分类器复算值）、逐原料改动明细、改动种数与总克数、最优性结论、求解耗时。
- **送检选样页**（`/select`）：两张可增删行的配方表 + 名额输入，支持批量粘贴（每行 4 个整数）。
  - 展示选中配方（含待检序号）、**增量覆盖叶**明细（所属树/节点、训练样本数、1/n）、
    总收益（float 展示 + 精确分数）、穷举节点数与耗时；无增量时展示“不推荐送检”，
    未能证明最优时展示“待定”。
  - 启动时实测生成两类演示样例：**有增量**（返回推荐组合）与**无增量**（不推荐送检）。
  - 同样采用 epoch + AbortController：**修改配方或名额立即撤下旧建议，迟到结果不得恢复**。

## API

| 端点 | 说明 |
| --- | --- |
| `GET /` | 试配求解网页 |
| `GET /select` | 送检选样网页 |
| `GET /api/meta` | 模型规格（树数、深度、种子、阈值、特征名） |
| `GET /api/leaves` | 全森林叶目录：编号、所属树/节点、训练样本数、收益 1/n |
| `GET /api/samples` | 经实测的可行 / 无解样例，以及送检选样的有增量 / 无增量样例 |
| `POST /api/solve` | 试配求解；体：`{original, lower, upper, locked}`（各 4 元） |
| `POST /api/select` | 送检选样；体：`{tested: [[g,g,g,g]...], candidates: [...], slots}` |
